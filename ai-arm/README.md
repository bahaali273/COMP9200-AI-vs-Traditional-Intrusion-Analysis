# AI-Assisted Analysis Arm: Prompt and Output Disclosure

This folder contains every prompt sent and every output received for the
AI-assisted arm of the study. Nothing produced by the AI agents has been
edited, apart from the redactions listed in the "Redaction" section below.

## Tool setup

| Item | Value |
|---|---|
| Tool | An agentic AI coding assistant (command-line agent that writes and executes code), Claude model family (Anthropic) |
| Model version | Not pinned. Model selection was set to automatic, so the server chose the model; the exact model per run is unknown. |
| Execution mode | Three autonomous sub-agents launched in parallel by an operator session, each with a fresh context |
| Date | 2026-11-09; outputs written 14:32:18 to 14:33:00 (British Columbia time) |
| Python | 3.12.10, in a shared virtual environment `C:\unsw-runs\env` |
| Libraries | pandas 2.2.3, numpy 2.2.6, scipy 1.15.3, matplotlib 3.10.3, seaborn 0.13.2 (pre-installed by the operator and pinned) |
| OS | Windows 11 |

## Isolation

Each run had its own folder, `C:\unsw-runs\run1` to `run3`, outside the
repository. At the start, each folder contained only the two official CSV
files. The prompt told the agent to read and write only inside that folder.

|---|---|---|
| UNSW_NB15_training-set.csv | 175,341 | BEC7DD5EC88DC2A0CCC7A07879D338395ED7421750F675FD0339E07DFE0648FA |

agents did not modify the data.

## Prompts

The prompt each agent received is in `runN/prompt-sent.txt`. It has three parts:

1. **Operator note.** The working-folder path, the Python interpreter path, and
   a request to log every shell command to `_action_log.txt`. The logging
   request was added because no transcript export seemed to be available at the
   time; the platform transcripts were later recovered (see Outputs). This note
   is the only part that differs between runs (the folder number).
2. **Operating wrapper.** The top section of `protocol/agent-wrapper-prompt.txt`:
   one-shot job, no questions, isolation, failure behaviour, and a `report.md`
   deliverable.
3. **Task specification.** `protocol/system-prompt.md` (open-ended version 2):
   the research questions, the data, the five features and four rules. It does
   not prescribe any statistical method.

## Outputs

- `runN/final-message.md`: the agent's final chat message, verbatim.
- `runN/outputs/`: every file the agent created: code, numeric results,
  figures, `report.md` and the action log.
- `runN/transcript/transcript-raw.jsonl`: the platform's own log of the run.
  It was copied from the assistant's local session store after the runs, then
  redacted (see below).
- `runN/transcript/transcript.md`: the same log in readable form, generated by
  `verification/render_transcripts.py`. Only formatting was added.

Each transcript contains:

- every tool call with its full arguments, including shell commands and the
  complete text of every file written or edited;
- every tool result;
- the agent's short reasoning summaries (the platform replaced some with `...`);
- the final message.

The opening prompt is not stored in the log. It is in `runN/prompt-sent.txt`.

## Verification (performed by the operator after the runs)

`verification/` holds the operator's scripts and their results. They are not
part of the AI arm.

| Check | Result |
|---|---|
| Rerun each `analysis.py` from a clean copy of the data | All saved CSV, JSON and PNG outputs reproduced byte for byte in all 3 runs. This was checked before redaction; see the note on the OS build string in "Redaction". `run2/cat_summary.txt` came from a separate command that read `results.json`. That command is recorded in the run 2 transcript. |
| Cross-run agreement on headline numbers (`compare_runs.py`, `cross_run_headline.csv`) | Identical effect sizes for all 5 features in both partitions. Maximum difference: 5.6e-17. |
| Claim audit: 21 numeric claims sampled from the reports (`audit_claims.py`, `claim_audit.csv`) | 20 correct, 1 wrong. Run 1 reports "no duplicate rows". Its transcript shows a one-off check, `d.duplicated().sum()`, run on the full table including the unique `id` column, so the count is always 0. Excluding `id`, there are 67,601 duplicates in train and 26,387 in test. This is a method error, not an invented number. |
| Extra checks (`extra_checks.py`, `generic_sensitivity.csv`) | The baseline's U statistic reproduces exactly. Effect sizes were recomputed with the Generic category excluded. |
| Isolation (`render_transcripts.py`) | Every path touched by every tool call (file paths for writes and edits; shell commands and working directories) is inside the run's own folder or is the shared Python interpreter. No run read or wrote anywhere else. This was checked against the platform log, not the agents' self-reports. |

All verification results were regenerated after the redaction and were
identical to the results before it.

To rerun the checks, run these from the repository root, with the dataset CSVs
in `../data` or in a folder named by the `UNSW_DATA` environment variable:

```text
python ai-arm/verification/compare_runs.py
python ai-arm/verification/audit_claims.py
python ai-arm/verification/extra_checks.py
python ai-arm/verification/render_transcripts.py
```

## Limitations of this setup

- **Transcripts recovered after the fact.** The platform's own log of each run
  was copied from the assistant's local session store after the runs; it was
  not a documented export. Some reasoning summaries are redacted by the
  platform, and the opening prompt is stored separately. The agents'
  self-reported action logs are incomplete (2 or 3 entries each), so use the
  transcripts instead.
- **Context file injected.** The platform automatically added a user-level
  instruction file, `latex-in-markdown.md`, to every run. It covers how to
  format maths in chat output and contains no analysis guidance. It was part of
  each run's context but not part of the prompt.
- **Model not pinned.** The three runs may or may not have used the same model,
  so run-to-run differences cannot be attributed to sampling alone.
- **Operator-provided environment.** The libraries were pre-installed, so the
  AI did not choose or install its own environment.
- **Shared model lineage.** The three runs produced near-identical code:
  identical plotting blocks, and identical figure files in runs 1 and 3. This
  suggests one model's habits rather than three independent analysts.
